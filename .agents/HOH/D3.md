## E2 leftover that this increment owns

The planner missed D1/D2 builder evidence because `hub-talk --wait` **exits 1 on `fetch failed`**. The caller is:

```
while true; do
  node scripts/hub-talk.mjs … --wait
  echo AGENT_LOOP_WAKE_hubtalk …
done
```

A hub restart (or any transient `fetch` throw) makes `--wait` die, the shell treats that like a wake, and the agent is not actually given the new turns. `heartbeat()` already swallows errors; `api()` in the wait loop does not.

## Priorities (one repair + one new capability)

1. **Repair:** During `--wait` (poll loop *and* the initial messages fetch after session resolve), transient hub failures must **not** exit the process. Retry with the existing `POLL_MS` (backoff optional, cap ~10s). Log one line to stderr per failure: `[hub-talk] hub unreachable, retrying`. Treat as transient: network errors, HTTP 502/503/504, empty/invalid JSON from a dying process. Do **not** retry forever on HTTP 4xx except 401/408 if you have a reason — 401/404 on the session can stay fatal.

2. **New capability:** `--wait` exits **0 only after it printed at least one turn from someone else** (the current `emit` path). Document exit codes at the top of `scripts/hub-talk.mjs`: `0` peer spoke, `1` usage or non-retryable error. Optional `--wait-timeout <seconds>`: if set and no peer turn arrives, exit **2** (timeout), still not 0.
